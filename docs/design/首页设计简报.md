# 新境游戏工具箱 · 首页设计简报

日期：2026-10-24（Asia/Shanghai）。阶段：视觉方案设计，尚未选择方向或开始首页代码实现。

## 设计目标

让玩家打开新境后，先获得个人问候，快速继续最近玩过的游戏，浏览/搜索全部游戏，同时看见少量与当前游玩有关的工具和系统状态。

参考：[NexBox UI 风格分析](../analysis/NexBox-UI风格深度分析.md)、[功能全景与实现分析](../analysis/NexBox-功能全景与实现分析.md)、[原仓库](https://github.com/MuLiuSaMa/NexBox)。

保留参考中的浮动导航、柔和圆角、可选玻璃、多色功能图标和个性化背景；强化游戏内容与可读性，避免把所有工具平均铺满首页。

## 画幅与信息层级

- 桌面设计画幅：1440 × 1024。单张图只展示一个完整首页方向。
- 主要任务：继续最近玩过的游戏。
- 第二层：全部游戏卡片，包括搜索、收藏/平台筛选、添加本地游戏。
- 第三层：硬件摘要、游戏模式、Win 键保护、每日密码及少量快捷操作。
- 公告、远程连接、心境、随机图片和社区入口采用简洁辅助区；不与游戏启动争抢视觉焦点。
- 全局导航为其他模块提供入口，不在本次设计中展开其他页面。

## 功能与呈现安排

| 功能                   | 首页呈现                                        | 后续交互/实现要求                                          |
| ---------------------- | ----------------------------------------------- | ---------------------------------------------------------- |
| 用户问候               | 用户名、头像、周末/时段问候、简短副文案         | 本地昵称优先，允许修改；不强制云账号登录                   |
| 最近玩过               | 3 个最近游戏，突出继续游戏与上次游玩            | 按实际最近启动时间排序；首次使用显示引导                   |
| 全部游戏               | 示例 6 款游戏卡片，清晰显示名称、平台和启动动作 | 本地 EXE、Steam 等来源分别接入；收藏、搜索、筛选、目录定位 |
| 添加游戏               | 明确的“添加游戏”按钮                            | 文件选择后识别图标/名称，可编辑；校验路径                  |
| 游戏模式               | 默认/常规/竞技的简洁入口                        | 呈现实际状态，说明影响；不能写成保证提升性能               |
| 游戏时禁用 Win 键      | 小型明确开关                                    | 状态反馈与游戏检测边界；独立于模式开关                     |
| 硬件摘要               | CPU、GPU、内存的一行摘要或精简侧区              | 使用真实数据与不可用状态；首页不堆满专业指标               |
| 每日密码               | 三角洲快捷入口/今日数据摘要                     | 在线失败/未更新状态明确，不展示假密码                      |
| 手机远程               | 未连接与配对设备入口                            | 用户主动开启；设备状态与撤销入口；避免暴露令牌/IP          |
| 公告                   | 单条最新内容与更多入口                          | 低频更新，不打断主任务                                     |
| 随机一言/心境/随机图片 | 一条安静文案及扩展入口                          | 支持显隐，不强占游戏区域                                   |
| 文档/反馈/社区         | 侧栏底部或辅助区的分组入口                      | 外部跳转有可理解标签                                       |
| 首页自定义             | 小型“自定义首页”入口                            | 后续配置卡片显隐、排序、背景与密度                         |
| 今日人气               | 可选，不默认展示虚构实时人数                    | 参考项目为随机数；不能包装成真实在线统计                   |

## 三个待生成方向

### 薄荷工作台

浅色、中性留白、薄荷绿强调，保留轻微磨砂外壳。最近玩过采用三张并列横向卡，全部游戏使用三列两行。硬件与保护开关浓缩成一条辅助带。优先内容秩序和阅读稳定性。

### 玻璃游戏桌面

延续 NexBox 的壁纸与漂浮表面：柔和、低干扰的插画背景，内容区有足够不透明度。最近游戏以一个主推荐区配两个小入口，全部游戏分布在左侧主区域，右侧窄区容纳模式、硬件、密码/远程入口。突出个人桌面的空间感。

### 夜航控制台

沿用现有新境的深蓝灰/深绿底与浅薄荷强调，以更沉静的深色磨砂表面承载游戏封面。最近玩过采取封面主视觉与紧凑时间序列，全部游戏使用四列紧凑网格。工具状态浓缩在页头或下沿，强调夜间使用与快速定位。

三个方向需在布局、内容权重和辅助区位置上有实际差异，不只换色。最终编号按生成图在聊天中实际显示的顺序确定。

## 视觉约束

- 字体以中文可读性为先，正文约14–16px，主次有层级，不滥用极小字。
- 主题色默认参考薄荷绿；浅色主按钮使用深色文字。
- 有图标的导航尽量保留短标签，避免纯记忆导航。
- 图标语义按 Font Awesome 可实现的图标规划，不使用表情符号替代界面图标。
- 卡片属于游戏对象；普通信息条目不逐条套重边框，不做层层卡片嵌套。
- 游戏封面有真实内容感，尺寸比例统一；不将壁纸作为可读性障碍。
- 强调游戏启动与内容浏览；不在产品界面展示开发框架、缓存路径、Rust/TypeScript 等实现细节。
- 准心、滤镜、内存清理等仅作入口，不将未接通能力描述为已运行。

## 实现边界

现有项目仅有基础概览、偏好设置和少量 IPC。此次设计不意味着游戏扫描、启动历史、硬件传感器、手机互联已经实现。选定视觉方案后，应逐项规划数据来源、权限、空态、失败态与持久化，不能仅用假数据完成表面交互。

前端继续使用 React + 严格 TypeScript、Tailwind CSS、Font Awesome，动效使用具有生命周期清理和减少动态效果支持的 GSAP；后端沿用 Rust/Tauri 的现有边界。
