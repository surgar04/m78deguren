# 统一 HUD

## 入口与数据流

设置 → 高级 → 统一 HUD，或工具 → 统一 HUD。原灵动岛和性能叠加层入口统一指向此处，运行时只有一个 `hud` 辅助窗口。

普通模式轮播用户选择的系统方案；有 Windows 媒体会话或进行中的下载时自动插入相应内容，结束后移出。自动模式在识别到游戏时切换性能视图，退出游戏后恢复普通队列。手动普通／游戏模式用于兼容特殊游戏。

| 内容                                                                 | 实际数据来源                                                      |
| -------------------------------------------------------------------- | ----------------------------------------------------------------- |
| 原项目的 12 种内置方案、变量、表达式、格式化、条件色、时间与网络目标 | 迁入的上游纯数据引擎，位于 `native/hardware-monitor/Hud/Upstream` |
| 温度、使用率、显存、内存、网络及设备变量                             | 既有硬件助手的一份采样，后台引擎只读已发布的不可变快照            |
| 媒体标题、作者、播放状态、专辑和进度                                 | 既有 Windows GSMTC 媒体服务；没有时间线时不生成虚假进度           |
| 下载任务和字节进度                                                   | 既有 Rust 下载管理器，最多同时轮播 8 个活动任务                   |
| 游戏 FPS、1% Low、0.1% Low                                           | 既有 Rust ETW Present 事件统计；不向游戏注入代码                  |
| 显示器／指定窗口的原项目 FPS 方案                                    | 按需运行 ECPFrames，固定哈希及父进程看门狗；离开方案停止会话      |

游戏识别结合 Steam／本应用快捷启动路径、前台进程、游戏引擎模块与全屏图形程序特征；支持添加和排除 EXE 名称。反作弊、受保护进程或不具备这些特征的游戏可能无法自动识别，应使用显式名单或手动游戏视图。桌面 HUD 不能保证盖在独占全屏之上。缺少权限、硬件能力或驱动时显示不可用状态，不自动提权或安装驱动。

## 上游来源与视觉迁移

固定来源 `GlacierGlimmer/zmd-charge-plus`，提交 `dd17813e682215f3b91d17b40963c34cb8c64a95`，MIT。许可与作者声明见根目录 `THIRD_PARTY_NOTICES.md`，原文随 MSI 分发。ECPFrames 的对应 C++ 源码与构建说明位于 `native/ECPFrames`。

复用原项目的胶囊比例、主题色、35 个图标路径、圆环和 Inter 字体；完整、简洁、翻滚三种动画迁为 GSAP。完整动画按上游 6 秒时标重现入场、涟漪、标题、收缩及读数出现，常驻时停在最终状态。只在场景／动画配置变化时运行，不随每个读数重播。减少动态效果偏好优先。

窗口支持目标显示器、九宫格锚点、拖动及保存位置、缩放、透明度、锁定穿透、置顶、热区呼出和电源变化提示。内容支持队列排序、手动切换、自定义模板及图标、条件色、阈值／变化／转为真触发及冷却时间。触发规则在变量库标签中配置，只有启用规则需要的变量才在隐藏期间继续采集。

## 资源与安全边界

- 复用已有 .NET 硬件助手，不引入 Avalonia 或另一份 UI 运行时；删除旧的完整 PresentMon 可执行文件。
- Rust 每秒编排并推送小快照，鼠标命中检测独立为 100ms，穿透属性只在变化时更新。后台慢采集最多一个任务；隐藏时停方案采集，禁用且没有预览租约时释放 HUD 独占采集资源。
- 原始硬件历史不复制到 HUD。帧交换链最多 512 个，每个时间窗口最多 4096 项。外部 HTTP 请求超时 8 秒，响应体最多 1 MiB，不跟随重定向。
- 表达式不执行 JS、HTML、文件操作或命令；限制长度、递归深度和数值格式精度。IPC、配置及外部响应分别验证，导入最多 512 KiB。
- DeepSeek 密钥及自定义请求头使用当前 Windows 用户的 DPAPI 保存；前端只回传掩码，导出不包含凭据。变更数据源地址后必须重新输入凭据。导入后 HUD 与外部 HTTP 数据源均关闭，等待用户核对启用。
- HUD 辅助窗口只能读取自己的快照、切换内容、控制媒体、移动自身和打开设置；配置、文件操作和系统工具仅主窗口可用。
- 配置损坏时保留原件并以关闭状态恢复默认，避免阻止整个应用启动。旧开关只迁移一次并立即保存为新的独立配置。
- 开发验收使用 `.cache/verification` 下的独立数据目录，写入保护保持开启；不安装驱动、不写系统配置、不进行真实安装。

## 检查命令

通过项目入口运行 `typecheck`、`lint`、`test`、`test:hud:native`。`rust:clippy`、`rust:test` 验证原生接口。修改硬件助手源码后必须先执行 `scripts/build-hardware-monitor.ps1`，生成真实发布件和来源哈希清单，再进行 Rust 构建。

`desktop:test:dev` 启动 D 盘隔离桌面端；就绪后运行 `test:hud:desktop`，证据保存到 `.cache/verification/hud-desktop`。测试结束恢复原 HUD 配置。开发检查结果以本次实际日志为准；旧 MSI 不包含本次尚未重新打包的修改，不能据此宣称新版已发布。

### 性能实测的适用范围

在本机调试桌面端、开发服务器开启的条件下，对应用进程树分别稳定采样约 16 秒。独立 D3D11 测试窗口的 CPU 不计入应用，硬件助手及 WebView2 子进程计入。

| 状态                    | 整机 CPU 占比 | 私有内存  |
| ----------------------- | ------------- | --------- |
| HUD 关闭                | 0.47%         | 594.5 MiB |
| 普通方案                | 1.15%         | 667.9 MiB |
| 游戏视图，帧采集关闭    | 0.81%         | 669.9 MiB |
| 游戏视图，真实 ETW 采集 | 0.75%         | 670.0 MiB |

本次游戏 ETW 状态相对关闭状态增加约 0.29 个 CPU 百分点、75.5 MiB 私有内存。这是短时调试实测，存在采样波动，不代表正式安装版的性能承诺。没有引入第二套 UI 框架或新的前端／NuGet 依赖；新增小型 ECPFrames 采集器，同时移除未使用的旧 PresentMon 可执行文件。正式包体大小需以后续重新构建的 MSI 为准。

真实桌面、游戏、媒体、下载及性能检查分别使用 `test:hud:desktop`、`test:hud:game`、`test:hud:media`、`test:hud:download`、`test:hud:performance`。本地证据保存在 `.cache/verification/hud-desktop`，测试仅使用隔离档案并恢复原配置。远程 CI 未运行。
