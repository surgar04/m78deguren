# 优化页面实现说明

> 本文保留初版设计还原的历史记录；其中“模拟数据、六类设置、未接入系统服务”的描述已被后续实现取代。当前版本为 **201 项真实配置、11 类、逐项确认及备份撤销**，请以 [系统优化全量实现与验收](系统优化全量实现与验收.md) 为准。

## 视觉与路由

独立路由`/#/optimization`，以本轮用户附件为唯一视觉目标，原样保存为`docs/design/optimization-assets/reference-selected.png`，1487×1058。首页/游戏库/硬件/工具继续使用同一外壳；优化导航选中并进入独立页面。

主屏还原搜索、检测当前配置、修改记录、六类卡片、常用设置及底部说明。复用MiSans、公共壁纸、品牌、头像、Font Awesome、玻璃令牌与GSAP作用域/减少动态效果处理，不渲染整页截图或手绘替代图标。

## 模块边界

- `src/pages/Optimization.tsx`编排目录查询、搜索、打开分类和设置。
- `src/features/optimization/types.ts`声明目录、设置、目标值和草稿契约。currentValue为null时代表未检测。
- `repository.ts`提供TanStack Query唯一优化目录缓存。
- `model.ts`负责搜索归一化、分类/设置匹配、目录选项白名单与草稿投影；不修改源目录。
- `store.ts`通过Zustand仅保存用户选择的ID和目标值，不复制业务目录、当前读数或修改记录。
- `OptimizationCards.tsx`负责分类/常用入口和显式图标映射。
- `OptimizationDialogs.tsx`处理分类详情、目标选择、草稿预览、检测与历史说明。
- `optimization.css`维护实测排版、交互状态和响应式重排。

## 交互与边界

分类入口可进入所属配置列表，常用设置可直接进入具体配置。目标值从当前设置声明的选项选择，加入前再次按目录校验。草稿支持更新、预览、单项移除和清空；同一设置不会产生重复记录。失效ID或已下线选项不生成待应用项。

草稿仅表示用户的待应用意图，页面当前状态继续为未检测；不把草稿写成成功历史。修改记录为真实的未发生修改状态。配置读取、写入、系统服务管理以及恢复接口尚未接入；检测按钮明确说明未连接，不产生假检测结果。本轮没有执行任何系统优化，也没有修改注册表、系统文件、服务或原生权限。

多级详情复用同一个原生dialog，保留最初页面触发器；切换内部视图时聚焦新控件，最终关闭恢复原始按钮。编辑器按设置ID重置局部选择；删除预览行前先将焦点交给稳定的对话框内容，避免卸载按钮后丢失焦点。预览使用真实table及行列标题，窄屏仅允许表格区域局部滚动。

## 模拟数据与移除

所有优化演示业务数据继续集中在`src/features/home/data/demo.ts`的`OPTIMIZATION_DEMO`，沿用统一标记`@design-mock ZHENJING_HOME_MOCK`。六类名称、描述、别名、图标/颜色、常用入口、设置选项、功能说明及null当前值都由同一数据模块提供。没有默认草稿、伪造检测、性能评分、提升百分比或成功修改记录。

`VITE_HOME_DATA_SOURCE=empty`或`dev.ps1 build:empty`返回空目录；条件动态导入让演示模块在打包时裁剪。已保存的用户草稿ID不会凭空恢复目录项。接入真实服务时只替换repository，原生访问统一通过src/lib/desktop.ts并进行运行时校验，Rust再次验证设置ID及可用目标值；不得透传任意注册表路径或命令。

彻底移除演示时删除repository的演示分支及demo模块，并搜索统一标记、设备型号、工具/优化文案和打包JS。分类结构、空态和服务未连接提示是产品文案，不是第二份模拟目录。

## 检查与存储

前端测试覆盖全角与多关键词搜索、目录关系、未知当前值、目标白名单、失效/重复草稿、空模式、偏好损坏与水合边界；另执行现有完整工程检查。Windows发布以实际链接EXE为准，浏览器验证不等同于真实WebView端到端或远程CI。

本轮复用已有D盘图片，没有新生成图像或新增依赖。所有源码、校验、截图、缓存及构建输出均经D盘环境入口管理。最终对照、功能和构建结果见根目录design-qa.md与.cache/verification/optimization/build-final.json。
