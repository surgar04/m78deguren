# 本地日志与诊断

日志只保存在当前应用数据目录，不自动上传。开发机仍强制所有文件位于 D 盘；发布版使用当前 Windows 用户的数据目录和既有存储策略。日志与账号、设置、游戏、媒体、更新安装记录分离。

## 事件和覆盖

| 链路                            | 记录内容                                                                    | 明确排除                                      |
| ------------------------------- | --------------------------------------------------------------------------- | --------------------------------------------- |
| 应用生命周期                    | 会话开始、正常退出、上次未正常退出、启动失败                                | 系统用户档案、命令行和环境变量                |
| Rust                            | 现有 log 调用统一 JSONL 脱敏；统一服务错误、panic、后台任务耗时/中断        | 请求/返回正文、原始异常链、用户文件正文       |
| 前端                            | React 渲染失败、全局错误、Promise 拒绝、查询与变更失败、警告/错误控制台     | 未知对象序列化、账号、会话票据                |
| IPC                             | 固定命令/动作、随机关联 ID、耗时、成功/失败；成功监控读取采样               | 输入值、返回值、搜索内容、目录选择结果        |
| 工具、首次启动、系统优化、Steam | 经过统一 IPC 和服务错误入口；Windows 任务有开始/完成/中断                   | 系统配置快照、登录项、游戏/程序路径           |
| 下载和更新                      | 下载任务生命周期、重试错误、MSI 安装开始/失败；安装原始日志保持原有独立位置 | 下载签名 URL、包凭据、未脱敏 MSI 原始日志附件 |
| 硬件/HUD/.NET                   | 进程异常及未观察异常类型，专用轮转日志；原有状态错误沿原生服务记录          | 硬件序列号、完整进程列表、完整系统信息        |
| 音乐                            | 独立宿主错误、浏览器/读取/验证阶段、固定原因代码，与主日志汇合              | Cookie、请求头、歌词/媒体正文、密码和平台响应 |

前端关联 ID 用于配对一次 IPC 的开始和结束；后台任务有独立关联 ID，结合会话、模块与时间定位。它不是向第三方服务注入的分布式追踪 Header。

## 格式、性能和保留

每行是独立 JSON：schema、UTC 时间、随机会话 ID、应用版本、级别、模块、事件、动作、随机调用 ID、耗时和脱敏说明。特殊字符由 JSON 转义，不能插入伪造的新日志行。

- 默认 Info；仅应用内部 Debug 可临时开启，30 分钟自动关闭，不放开第三方网络正文/请求头日志。
- 应用日志新文件 2 MiB、轮转保留 6 份；14 天历史清理。旧版较大归档可能存在，反馈时应使用脱敏导出，不能直接假定旧文件已脱敏。
- .NET 故障日志独立四份、每份约 256 KiB；只写固定事件与异常类型。
- 前端队列最多 128 条、每批 64 条、间隔 1.5 秒；重复错误短时合并，溢出保留计数。高频成功读取每分钟采样，不逐帧记录。
- 原生最近 200 条事件保留在有界内存中，日志查看最多 500 条。磁盘不可写时不能保证持久化，但仍可在进程存活时获取这些事件；日志自身失败不能引起递归崩溃。
- 前端入站全局每分钟最多 600 条，超出会留下限流事件和统计；Rust 服务错误与独立崩溃记录不经过这一前端限流。
- 查看、导出和清理的文件操作在阻塞池执行；不在采样路径遍历历史日志。

## 查看、导出和清理

设置 → 高级 → 日志与诊断。支持级别/文本筛选、暂停自动刷新、详细模式、打开目录、明确确认清除，以及通过原生文件选择器导出 JSON 诊断包。

默认诊断包包含最近最多 500 条脱敏事件、版本/系统架构和经字段白名单重建的音乐授权阶段。不会打包原始配置、媒体、数据库、浏览器档案、环境变量或会话仓库；即使旧日志出现未知嵌套对象也不会原样附加。目标文件已存在时拒绝覆盖，写入失败清理本次未完成文件。

辅助窗口只能提交有界的诊断事件，不能读取、导出、清理或修改详细模式。主窗口未完成开发者认证时同样只能上报事件，日志管理不能绕过身份限制。

## 失败边界

Rust panic 使用独立文件并尽力同步写盘，避免在主日志锁内再次记录；启动失败另存脱敏原因。断电、磁盘故障、操作系统强杀、原生访问冲突或启动早于数据目录可用时，无法承诺捕获最后原因。会话未正常结束标记只能提示异常结束或另一个实例，不能独自判定崩溃。

本系统不生成内存转储，不拦截系统全局事件，也不收集任意桌面内容。真实账号、特定用户网络与驱动环境的问题仍需要相应环境回归，日志的目标是让失败可见、可定位，而不是伪造成功结果。

## 本机发行验收

`scripts/verify-logging-desktop.ts` 只启动刚通过 MSI 解包核对的实际 EXE，使用新的 D 盘隔离档案，不读取真实账号。普通用户上下文可通过本地 CDP 检查入站脱敏、有界快照、实际轮转和异常结束标记。

管理员上下文中的 WebView2 会忽略环境变量调试参数，见[微软安全说明](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/security#for-an-elevated-host-app-use-appropriate-override-flags)。此时执行 `node scripts/verify-logging-desktop.ts --native-only`：预置超过配额的合成旧日志，再启动包内程序验证实际轮转、JSONL 格式和强制结束后的新会话检测。测试必须等到新会话 ID 对应的启动完成事件，不能读取旧启动行便判成功。此模式不声称验证了 CDP 入站或快照，脱敏及导出字段边界另由 Rust 测试检查；结果文件会明确列出已检项目和跳过项目。验收不修改注册表、系统策略或发行 EXE 的调试配置。
