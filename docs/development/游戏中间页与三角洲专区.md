# 游戏空间与三角洲专区

游戏空间是 `game-room` 独立原生窗口，不是主页面中的遮罩。首页提交游戏启动请求前显示准备页，原有进程助手随后报告真实进程身份；运行检测也能直接触发页面。同一 PID 和创建时间只提升焦点一次，用户关闭后不会被轮询重新打开。页面默认置顶，可从首页“游戏空间”或本页设置管理；未实现专属工具的游戏只显示通用性能区域。

## 页面与服务

| 路由                            | 内容                                                                                                     |
| ------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `/delta-force`                  | 角色摘要、共享实时监测、每日密码、改枪码分类/武器/搜索/分页、复制、点赞、报告、投稿审核、官方地图与壁纸  |
| `/delta-force/other-platforms`  | 码枪堂、ANXU、主播改枪码、小涛查，固定入口的独立无应用权限窗口                                           |
| `/delta-force/random-equipment` | 地图、干员、武器、弹药、头盔、护甲、特殊任务；绝密/永夜、不带手枪、跳过动画                              |
| `/delta-force/stats`            | WeGame 官方 QQ/微信扫码、缓存及刷新、个人详情、对局和详情、分析、出货、藏品；烽火/全面战场与官方赛季筛选 |
| `/delta-force/streamers`        | 冠军导航资料源的真实主播目录、搜索和增量显示                                                             |
| `/delta-force/streamers/:id`    | 全部分组参考配置及外设、复制、隐藏缺项；不自动写入游戏配置                                               |

前端唯一入口为 `executeGameRoom`，所有参数由 Zod 与 Rust 重复验证。只有本地主窗口和 `game-room` 可以调用；官方授权和第三方网页无应用 IPC 权限。后台使用有连接池的固定 HTTPS 数据源、超时、有界响应、图片魔数/尺寸校验、受限并发和缩略图缓存，不放宽全局 CSP。社区写入仅在用户点击对应按钮后执行，不在开发验收中自动投稿、点赞或报告。

## 数据真实性与性能

硬件采样与原有硬件页/HUD 共用；游戏窗口每秒只接收所需摘要和最近 60 个样本，不复制全部原始传感器。FPS、1% Low、0.1% Low 来自共享 Rust ETW Present 统计，FPS 用最近 1 秒，Low 用最多最近 60 秒且保留样本数门槛。这样 60 FPS 游戏可在积累 1,000 帧后取得 0.1% Low，不会被旧 10 秒窗口永久截断。帧率启动只接管空闲会话，退出按 generation 租约释放，不能停止后来被别的页面接管的会话；失败间隔重试，不自动申请管理员权限。缺失值显示“—”。

网络区域提供网卡吞吐和波动曲线。吞吐不是游戏服务器 RTT、抖动或丢包；没有可靠数据时不生成这些指标。游戏时长来自检测到的真实进程会话。大型战绩/藏品缓存仅在采集修订变化或用户刷新时跨 IPC 读取。

## WeGame 授权

扫码在官方 `https://www.wegame.com.cn/helper/df/score/` 独立 WebView2 中完成，由官方页面提供 QQ/微信流程。认证资料留在专用 WebView2 档案；不提取其他浏览器 Cookie，不将登录票据、账号密钥或完整请求正文写入日志。采集脚本仅在确切官方域名和路径运行，只请求固定只读业务方法；回传前剥离凭据及内部身份字段。

授权有等待上限、取消、窗口关闭和超时状态；采集按请求和会话身份隔离。完整刷新先重置旧角色缓存，避免切换账号后混合数据。退出清理专用登录档案及本机战绩，文件被占用时保留退出标记，清理前不复用旧会话。旧数据必须与“已验证登录”区分。

PPS、MMR、MES 和未来压力分布参考 NexBox 的公开客户端公式，并修正单位、时间顺序及负分边界。它们是有限历史样本的本地参考计算，不是官方隐藏匹配分或未来结果保证。赛季数据只使用官方赛季标识和时间范围；官方接口未返回的历史或藏品不补造。

## 粘滞键保护与恢复

游戏运行时默认临时关闭 StickyKeys 开启位、连续 Shift 热键和确认位；通过 Windows `SystemParametersInfo` 调用，不写入注册表或持久化系统配置。修改前原子保存原值，使用与进程控制相同的会话互斥锁。正常退出游戏、关闭策略及父进程退出看门狗均尝试条件恢复；其他程序已改变设置时保留恢复记录，不覆盖其修改。页面提供明确的原值恢复入口。

通知由 Windows Shell 的原生 `NotifyIcon.ShowBalloonTip` 呈现，尊重系统通知策略。系统禁用通知时不能保证显示，但不会影响恢复记录。`ZHENJING_RESTRICT_WRITES_TO_D=1` 的本机验收只读检测，不修改真实辅助功能、进程优先级或安装系统组件。

## 来源与验收边界

### 入口与本地检查

首页快捷启动标题旁的「游戏空间」可手动打开独立页面。首页登记为游戏的程序在提交启动请求前先显示页面，已识别进程则按 PID 与创建时间自动显示一次；关闭页面不会退出游戏，也不会在同一会话反复抢焦点。页面右上角可调整自动显示、置顶和粘滞键保护。

`powershell -NoProfile -ExecutionPolicy Bypass -File .\dev.ps1 test:game-room:native` 检查原生 DLL 清单、Win32 读取结构、恢复记录校验和开发保护。`test:game-room:desktop` 连接本地 9223 调试端口，要求数据目录恰为 `.cache/verification/game-room-desktop-data`，验证独立窗口、真实硬件摘要、公共社区/主播资料与图片、官方授权取消。该脚本不会执行社区写入或登录私人账号。

另使用限定 45 秒的自有 D3D11 渲染程序验证了自动识别、弹窗、真实 ETW FPS 和两类 Low、手动关闭后不重复打开、进程退出时间。此结果不能替代真实反作弊游戏对 ETW 的可用性，也不意味着 CPU/GPU 的所有传感器在所有机器均存在。

随机装备基础目录来自 [NexBox](https://github.com/MuLiuSaMa/NexBox/tree/main/src/data/delta-roulette)，原 GPL-3.0 许可保存在对应数据目录。WeGame 同源采集、社区接口与参考评分依据其 `df_stats.rs`、三角洲页面和主播资料层重写；业务资料和图片版权属于各自权利人。组合程序遵循仓库根 AGPL-3.0。

自动验收使用公共只读数据源、独立 D 盘档案和自有渲染测试进程，不代用户登录私人账号，不执行真实游戏、投稿或系统修改。私人账号、赛季权限与官方数据源的实时可用性仍需真实账号验收；编译和模拟接口测试不能代替该结果。
