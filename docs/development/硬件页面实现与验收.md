# 硬件页面实现与验收

## 页面与功能映射

| 位置                        | 实现                                                                                                                                                     |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/hardware` 总览            | CPU/GPU/内存实时摘要、同源性能曲线、设备摘要、按传感器标识切换多 GPU                                                                                     |
| 设备信息                    | CPU 核心/线程、频率、L2/L3、架构和插槽；GPU 驱动/INF/设备标识/64 位显存；内存条、主板、BIOS、磁盘/分区、声卡、网卡、显示器与操作系统详情，支持分类和搜索 |
| 实时监测、`/sensor-monitor` | 原始传感器按硬件分组、展开/收起、硬件类型/传感器类型过滤、名称搜索、当前值与单位、本次会话的 min/max（清除记录时重置）                                   |

## 数据与安全边界

- `HardwareState` 是唯一服务；主窗口、首页和传感器窗口共享该服务，不在 React 中累计第二份历史。
- `native/hardware-monitor` 使用独立、自包含的 C# 进程桥接 LibreHardwareMonitor 0.9.6。WMI、DXGI 和 Windows GPU 性能计数器补充型号、链路、显示模式和核显读数。慢速 GPU 计数器在独立线程查询，不阻塞主循环。
- 型号清单和实时读数分别建模：DXGI 名称会先去除首尾空格，避免同一显卡重复识别；多块同名显卡不按名称冒险串接系统补充读数。Windows 能识别但没有传感器的虚拟显卡保留切换入口，指标为空而非伪造零值。
- 助手和依赖运行环境按内容摘要释放到 D 盘；TEMP、配置、缓存及 .NET 解包目录均显式放 D 盘。Rust 校验协议长度、类型、有限数值、文本和时间戳，监控子进程退出/超时最多自动恢复三次。
- CPU/主板底层传感器只有在应用内明确确认、已有管理员权限且 PawnIO 已安装时才开启。没有驱动、权限或不支持时显示实际诊断与 `—`，不安装驱动、不主动提权。驱动管理沿用设置页的确认/恢复流程。
- 原始传感器窗口仅允许 `snapshot`，不能导出、清除、控制 ETW 或获取远程凭证。
- 远程接口不返回序列号、MAC、本地目录或完整设备信息。凭证放在 URL fragment，实际 API 用 Authorization；无外部脚本、无 CORS，校验 Host/Origin，并限制连接数量、请求大小和超时。
- 报告在 `数据目录/hardware/reports`；时序在 `数据目录/hardware/history`。内存图表保留最近 360 个点，历史按 16 MiB 分卷、最多 16 卷、最长 31 天，磁盘失败的待写缓冲上限 60 条。正常退出会先停止服务并刷盘。清除不删除报告和不属于本模块的文件。
- 单份报告最多 60,000 个原始点，超出时从真实点降采样，不生成新值。自定义范围精确到毫秒；HTML 使用内联脚本摘要 CSP，型号文本与 JSON 做转义。
- FPS 只统计真实 Present 事件，未收到事件显示不可用。瞬时值用最近 1 秒，Low 用最近 10 秒最慢帧的平均帧时间；1% / 0.1% Low 至少需要 100 / 1,000 帧。这里的 FPS 是 Present 提交统计，不等价于显示器实际扫描输出或游戏内逻辑帧。

## 构建与验收入口

```powershell
# 全部入口均在 D:\新境，环境只影响当前进程和子进程。
powershell -NoProfile -ExecutionPolicy Bypass -File .\dev.ps1 check
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-hardware-monitor.ps1

. .\scripts\env.ps1
cargo test --manifest-path src-tauri/Cargo.toml --locked --lib hardware:: -- --include-ignored --nocapture
# 上面的 ignored 只读实机测试不会安装驱动、启动 ETW 或开放局域网端口。
& .tools/node/node.exe scripts/verify-hardware-report.ts
# 桌面验收需先使用 tauri.test.conf.json 构建并启动独立测试档案，脚本会校验 dataRoot 后才清除测试记录。
powershell -NoProfile -ExecutionPolicy Bypass -File .\dev.ps1 test:hardware:desktop
```

桥接的源码、NuGet 锁文件和 EXE 摘要写入 `resources/hardware-monitor/manifest.json`；Cargo 构建检查一致性，不能把旧助手误打进新程序。离线报告与手机页面使用严格 TypeScript，经 `build-hardware-web.ts` 编译后由 Rust 内嵌。常规前端构建自动刷新这两个静态脚本。

本机只读验收覆盖真实型号、原始传感器、历史落盘、时间过滤、报告生成、清除和进程关闭。远程 API 另在回环地址验证鉴权和 Origin 拒绝，避免验收开放真实局域网。驱动安装、底层写操作不属于自动验收。远程 CI、真实手机/不同厂商机器的兼容性不能用本机检查代替。

## 2026-10-26 本机验收结果

- 前端严格类型检查、全量 ESLint、Prettier、Rust fmt 与全部目标 Clippy 均通过。前端 18 个测试文件共 64 项测试通过；硬件 Rust 专项 8 项通过，含显式启用的真实采样测试。首次 fork 工作进程启动超时后，使用单线程池完成全量前端复验。
- 测试配置下的 Windows EXE 实际链接并启动，使用独立 `D:\新境\.cache\verification\hardware-gui-final-data`；识别 23 个设备条目、49 项原始传感器，正确区分 NVIDIA GeForce 210 与无传感器的 GameViewer 虚拟显示适配器。
- 桌面 1200×800、760×560 无页面横向溢出；显卡切换、设备过滤、独立窗口、原始传感器搜索与收起、导出、清除及退出联动均通过，未发现页面脚本错误。
- 使用临时 D3D11 渲染进程验证真实 ETW：约 199.9 FPS，1% Low 78.5、0.1% Low 20.1，窗口内 1,178 帧。该数值只反映这次测试进程与机器负载，不是游戏性能承诺。
- Rust 实际导出的 HTML 在浏览器中验证十组图表、预设/自定义范围、无数据区间与恢复全范围；1200、390 像素宽度均通过，无外部网络请求和脚本错误。手机 API 的 401/200/403 鉴权与跨源拒绝在回环地址通过；没有自动开放真实局域网端口。
- 测试应用、监控子进程与临时渲染进程均已关闭。没有安装驱动或更改系统配置；未执行远程 CI、发布 Release 或验证真实手机及其他硬件厂商机器。调试端口仅出现在专用测试配置，不能将该测试 EXE 作为正式发布包。
