# 系统与硬件实现说明

## 路由与模块

独立路由 `/#/hardware`，复用WorkspaceLayout、公共Dock/窗口栏/壁纸/字体与GSAP生命周期。硬件导航项选中；首页与游戏库的硬件入口均进入该页。

- `src/pages/Hardware.tsx`：页签、时间窗、报告与传感器弹窗。
- `src/features/hardware/types.ts`：与数据源无关的快照/采样契约，null表示指标不可用。
- `model.ts`：比例约束、格式化、时间窗过滤、统计、版本化报告。
- `MetricCards.tsx`、`DeviceInformation.tsx`、`SensorTable.tsx`：摘要、配置与传感器数据呈现。
- `PerformanceChart.tsx`：Canvas折线、时间范围、图例及键盘/悬浮交互。
- `useCanvas.ts`：DPR、ResizeObserver与字体就绪重绘，卸载清理。
- `hardware.css`：基准布局及响应式重排，复用首页设计令牌。

## 模拟数据集中管理与移除

唯一业务种子继续位于 `src/features/home/data/demo.ts`，统一标记 `@design-mock ZHENJING_HOME_MOCK`。设备型号、当前读数、采样锚点、固定历史数组、采样间隔、网络速率和磁盘容量都集中在此文件，没有在Canvas或组件里随机生成读数。共享HomeData.hardware被扩展为HardwareSnapshot，首页和硬件页仍读取同一查询缓存。

仪表与序列末帧在测试中校对；时间窗从最新采样时间向前选择，排序复制结果，不修改查询缓存。最低/最高取自有效采样，不硬编码设计数字。缺失、NaN或无穷值不冒充0。

使用 `VITE_HOME_DATA_SOURCE=empty` 或 `dev.ps1 build:empty`，repository条件导入移除整个演示模块；空模式返回unavailableHardware结构，没有型号和历史种子。接入真实服务时替换repository并扩展来源枚举，在desktop.ts做运行时校验，Rust再次验证；删除demo分支及文件后搜索统一标记与构建JS。结构缺省值不是另一套模拟数据。

## 报告保存

网页预览可查看完整JSON并复制，不向浏览器默认下载目录写入。桌面端调用 `src/lib/desktop.ts` 的 `exportHardwareReport()`：

1. 前端检查UTF-8大小和返回回执。
2. Rust命令再次检查JSON大小、格式版本、报告类型、来源和采样数量。
3. `src-tauri/src/services/reports.rs`在spawn_blocking中执行同步I/O。
4. 路径仅来自宿主管理的D盘应用数据根目录，固定子目录reports。调用方不能指定文件名或路径。
5. 对根目录和最终目录进行规范路径检查，拒绝C盘/其他盘、父目录遍历及指向C盘的目录联接；create_new避免覆盖已有报告，失败不回退系统盘。
6. 默认输出 `D:\新境\.local\data\reports\hardware-report-*.json`，便携版随配置的D盘数据目录保存。文件明确保留demo/unavailable来源，不把模拟数据标成真实监测。

原生I/O测试确实在D盘写出并解析了JSON。浏览器复制按钮返回成功，但内置Browser Use虚拟剪贴板无法读回系统剪贴板，本轮没有声称端到端复制粘贴已验证。真实WebView中点击保存的端到端操作仍待独立运行环境验证。

## 能力与视觉边界

已实现总览、配置视图、监测视图、趋势过滤、曲线显隐、采样提示、键盘导航、传感器统计、报告预览/复制及Rust固定目录保存。尚未接入传感器、WMI/NVML、驱动、实时采集、游戏FPS识别；演示模式是固定快照，页面明确标注。

没有新建背景图片、图标贴图或手绘SVG。曲线和圆环是按数据绘制的Canvas，其他图标来自显式导入的Font Awesome。原稿的个别图标、字体和公共壁纸细节与当前正式资源仍有差异，不能描述为100%像素一致。具体截图与验收记录见根目录design-qa.md。
