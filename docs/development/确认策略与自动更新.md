# 确认策略与自动更新

## 二次确认

`confirmActions` 默认开启，查询尚未返回或配置损坏时同样按开启处理。`src/lib/confirmation-policy.ts` 统一规定可以省略重复询问的操作，页面不另存一份偏好。

关闭开关后，明确点击以下操作直接提交：游戏模式、自动游戏模式及游戏 Win 键策略、进程恢复、移除首页快捷入口、清理本应用缓存、清除硬件时序记录、向 Steam 请求安装或卸载游戏。Steam 客户端自身的确认、安装位置选择保持不变。

账号切换和移除、数据重置、系统优化、驱动、运行库、分区与迁移仍走原有逐项确认流程。省略应用对话框不放宽 Rust 的窗口权限、目标白名单、revision、一次性租约和输入验证。

## 更新状态机

1. 固定 GitHub Releases 检查仍每四小时执行，自动下载由原有偏好控制；用户主动下载也采用相同的完成后自动安装流程。
2. `UpdateService` 负责清单验签、固定仓库/稳定版本检查、下载长度与 SHA256、安装租约。未签名、错误版本或损坏文件不会进入可安装状态。
3. `update_runtime` 是独立原生后台任务：空闲时等待通知，存在下载时每两秒检查状态。主窗口隐藏或关于页未打开时同样有效，UI 轮询不触发安装。
4. 包已就绪后检查首次启动向导、游戏、有状态工具、显示模式事务、运行库安装及其他关键任务。忙碌时延后，空闲后继续，不强制终止游戏或工具。
5. 更新与工具修改共用 RAII 维护锁。再次复核实际文件，持久化 `settings/update-attempt.json`，然后等待维护助手就绪，才退出宿主。
6. MSI 使用 `/passive /norestart` 显示进度但不重复询问；Windows 权限策略仍生效。安装、事务回滚、重启健康检查复用现有维护链路。

同一版本和摘要已尝试过但应用仍运行旧版时，不反复自动安装；关于页保留“立即安装 / 重试”和“安装日志”入口。用户主动重试仍需有效原生租约和全部校验。尝试记录损坏时停止自动安装，不能当作从未尝试处理。日志及 MSI 失败回执位于应用维护目录。

开发构建以及 `ZHENJING_RESTRICT_WRITES_TO_D=1` 的本机验收在 Rust 与维护助手两层拒绝真实更新安装。测试仅验证状态边界、持久化恢复、协议、UI 意图及实际链接，不运行 MSI。

## 移除自定义导航

侧栏额外快捷项、导航配置表单、导航 IPC 操作、配置字段及对应样式均已移除。磁盘旧六项/八项配置先验证，再按摘要备份，原子提交仅包含轮盘的新格式。保留首页快捷启动和桌面八向轮盘；主导航的页面排序、可见性、侧边/顶部切换不受影响。

## 关键注释约定

- 模块注释说明能力边界与状态所有权；公开的关键函数说明前置条件、失败结果和恢复方式。
- 异步互斥说明锁的覆盖范围、获取顺序与释放方式；不把服务状态复制进另一个界面状态源。
- 涉及副作用的流程说明提交点、一次性凭据、持久化顺序和失败恢复，明确哪些步骤不能在开发机执行。
- 单位、时间范围和协议兼容性在边界处说明；不为直接赋值、普通循环或显而易见的 JSX 添加重复注释。
- 历史验收记录保留原语境，当前行为以本文件和对应实现为准，不把未执行的真实安装写成已通过。
