## 操作流程

1. 进入页面自动读取本机配置；“检测当前配置”重新扫描。显示 Windows 构建、扫描时间及真实分类状态。
2. 项目状态区分目标匹配、预设匹配、自定义、部分匹配、不适用和读取失败。查看详情可展开原始注册表路径、类型和读数；缺失值与数值零严格区分。
3. 单项、枚举或批量预设只生成用户草稿。草稿只持久化 ID 与目标值，不伪造当前配置或修改记录。
4. 生成预览时后端再次读取实际值，返回确切路径、类型、修改前后值和 600 秒有效的一次性凭据。此阶段不写注册表、不申请 UAC。
5. **所有项目都要逐项勾选**，再确认整体修改说明，才允许点击最终执行按钮。批量预设不跳过确认；关闭预览会释放未使用凭据。失败重试必须重新生成预览并再次确认。
6. 执行后以回执显示成功、失败、取消或待核实状态。状态重新扫描，不以客户端预估代替实际值。不自动重启或注销。
7. 修改记录提供整次备份撤销。批量参考恢复与备份撤销分开：前者写入参考恢复配置，后者恢复此次修改前的确切原值。

“安全优化”只选本项目白名单内低风险且适合该预设的项目；“增强优化”排除高风险和安全敏感项目；“全部优化”将可用项全部加入审阅。三种预设都跳过不适用、读取失败及已匹配的项，替换旧的待应用清单，避免旧高风险草稿混入安全预设。UAC、CFG、SEHOP、SmartScreen、防火墙、DCOM、SMB、系统还原等敏感项目提高为高风险。

## 分层与边界

- `scripts/import-optimizer.ts`：使用 TypeScript AST 静态解析参考配置，只接受固定注册表语法，不导入执行上游 TS 或 `.reg`。生成器校验 201 项、11 类及选项完整性，`--check` 检查输出是否漂移。
- `optimizer-catalog.json`：唯一执行目录，编译期嵌入 Rust 与原生脚本。产品分类文案为静态元数据，所有实际状态来自后端。
- `commands/optimizer.rs`：主窗口专用读取网关。辅助窗口不能获取优化目录、扫描或操作能力。
- `services/tools/optimizer.rs`：验证 ID、枚举、数量、重复项及回传值结构。前端无法提交任意注册表路径、外部脚本或命令。
- `windows/optimizer.ps1`：目标解析、扫描、预览、冲突合并及恢复校验。脚本和目录受现有内容哈希、受限任务文件与文件锁机制保护。
- `windows/optimizer.cs`：固定 Registry64 读写适配，保留原始类型与缺失状态。字符串不展开环境变量；DWORD/QWORD 保留无符号值，二进制、REG_NONE、多字符串均可备份还原。
- `system_changes.rs` / `windows/system.ps1`：复用一次性确认、原始用户 SID、D 盘备份、回执、失败回滚及同会话跨实例串行事务。其他工具继续使用各自有效期。
- 前端通过 `src/lib/desktop.ts` 和 Zod 访问。TanStack Query 保存目录、实际扫描与记录；Zustand 仅保存用户草稿。优化页不再引用 `OPTIMIZATION_DEMO`。

采用 C# 是为复用 Windows 提供的托管注册表类型 API，无需额外分发运行时或下载第三方二进制。异步 Rust 网关负责子进程调度、超时与输入边界。

## 相对参考源码的修正

1. **显卡实际定位**：参考文件中的 `0000` / `0001` 显示类模板按 PCI 厂商和实际设备 Driver 键解析，不把 NVIDIA 配置写到 AMD/Intel 设备上；无对应设备时显示不适用。
2. **共享 DirectX 字符串**：Flip Model 和独显优先共用值时按所属属性合并；应用、参考恢复均保留其他应用的未知属性。
3. **语音/输入隐私互相覆盖**：语音识别配置不再顺带删除输入个性化策略，避免两项同时应用产生冲突。
4. **参考恢复冲突**：广告/提示/推荐应用/键盘响应的 6 个共享值，其参考恢复文件给出不同目标。统一移除覆盖、继承系统默认，原参考值保留为 `referenceValue` 并增加审计说明；全量参考恢复不再相互冲突。
5. **删除键范围**：参考恢复文件的删整键操作缩小为仅移除本项拥有的值，不递归删除用户或其他程序的配置。备份撤销仅清理本次创建且仍为空的祖先键。
6. **不存在的服务**：不创建虚构服务键；部分服务缺失时说明跳过的目标，全部目标缺失时禁用操作。

## 事务与恢复

计划合并同一注册表目标，拒绝无法合并的互斥值；无变化时拒绝重复写入。每批记录原始类型、值、缺失键、目标、项目归属及原始用户 SID。UAC 使用另一管理员身份时，用户级目标仍指向发起用户的 HKU 范围。

执行先将任务、备份和初始回执写入 D 盘，Flush 到磁盘后原子替换。实际写入前重新核对预览指纹，每值写入后立即回读；失败逆序回滚。回执保留失败原因，不能把异常当成功。

恢复先核对整批目标、目录白名单及当前值。当前值只能是该批原值或目标值；第三方已改成其他值时整批拒绝覆盖。支持进程中断后部分已写入的恢复；恢复自身失败时亦尝试回滚到恢复前状态。备份中的路径或目标被篡改会被校验拒绝。该机制尽力回滚，不承诺 Windows 注册表具备跨进程原子事务；系统断电、保护策略或外部并发修改仍可能造成需要人工核实的结果。

源码、缓存、测试、构建、WebView、备份和日志均使用 D 盘。只有用户运行时确认的目标系统配置，按既有授权写入 Windows 注册表；开发验收不执行这些写入。

## 验证方式与证据

- `scripts/verify-builtin-readonly.ps1 -Operations optimizer-scan`：对本机真实注册表执行 201 项只读扫描，结果在 `.cache/verification/builtin-readonly/optimizer-scan.json`。
- `scripts/verify-optimizer-transactions.ps1`：以实际计划和事务代码、内存注册表适配器运行 11 项验证。覆盖全量应用及预设恢复、所有枚举、三厂商解析、共享属性、篡改拒绝、过期指纹、失败回滚、恢复冲突、恢复失败及中断恢复。真实系统写入为零。
- `scripts/verify-system-transactions.ps1`：共享事务原有 7 项回归。
- 前端测试覆盖预设风险、状态真实性、草稿迁移、确认门禁、失败重试及关闭预览后的凭据释放；Rust 测试覆盖目录完整性、未知/重复输入、同意、凭据过期及单次使用。
- `scripts/smoke-optimization.ts`：连接独立测试配置的原生 WebView2，验证真实 IPC、全部分类、实际扫描、全部应用/恢复预览、风险、枚举、确认及响应式。只允许读取、预览、释放凭据，代码没有执行系统变更的验收入口。
- `scripts/smoke-tools.ts`：原有内置工具与辅助窗口权限回归。
- 发布须实际链接 Windows EXE，并运行发布启动检查；证据与截图保存在 `.cache/verification/`。以最终实际执行结果为准，远程 CI 不等同于本地验证。

## 效果边界

这是参考项目**全部 201 项配置操作**的实现，而非对任何 Windows/驱动版本的性能承诺。目标匹配只表示注册表读数匹配，不证明系统已采用该值或性能提升。部分未公开、过时或受策略保护的配置可能被当前 Windows、驱动或域策略忽略；某些配置需要重新登录/重启，服务启动策略不等于立即停止正在运行的服务。

本机只读扫描和内存事务验证不能替代各型号显卡、各 Windows 版本或真实系统破坏性测试。验收不会关闭安全机制、停止服务、安装驱动、重启或触发 UAC。参考实现的完整覆盖与实际设备可用性分开呈现，不伪造不支持设备上的成功结果。

注册表类型语义参考 [RegistryKey.GetValue 官方说明](https://learn.microsoft.com/en-us/dotnet/api/microsoft.win32.registrykey.getvalue)，提权行为参考 [Windows UAC 设置说明](https://learn.microsoft.com/en-us/windows/security/application-security/application-control/user-account-control/settings-and-configuration)。
