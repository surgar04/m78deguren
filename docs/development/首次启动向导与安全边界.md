# 首次启动向导与安全边界

全新档案从原生窗口直接进入 `#/setup`，主工作区在准备完成前不挂载。阶段、身份选择和操作结果由 Rust 持久化；刷新或重启不会自动重放安装及磁盘操作。已有使用记录的升级用户继续进入工作区。

## 准备顺序

1. 磁盘：读取固定卷、容量和空间。仅一个可见固定系统卷且 D 盘符空闲时提供分盘选择。管理员只读预检后，用滑块选择容量，再展示磁盘身份、容量、布局记录和恢复说明。用户确认外部备份并输入“创建 D 盘”后才执行。
2. 迁移：应用位于系统盘时可选择非系统 NTFS 固定盘。准备同版本完整 MSI、验证签名清单、SHA256、长度及 MSI 产品身份后才提供确认。用户输入“迁移臻境”后退出，通过 MSI 卸载／重装迁移；快捷方式和持久化数据位置同步更新。
3. 硬件：调用真实硬件采集器，保存设备档案。
4. 显卡：显示真实型号和驱动版本；通过 Windows Update 查询当前设备的兼容显示驱动。该结果不代表全部厂商测试版或官网版本。逐项确认后备份当前第三方显示驱动并安装更新；备份失败则停止。
5. 运行环境：读取实际缺失项，使用工具页既有的微软白名单下载、哈希和签名验证链路；每项运行库仍需明确安装确认和 Windows 提权。
6. Steam：查询注册表、运行进程、常见路径和有界目录搜索，并支持手动定位。找到后保存实际安装位置和游戏库；未找到可选择磁盘安装官方 Steam。不会执行账号切换。
7. 背景：默认背景、用户图片或不超过 15 秒的视频；视频静音循环，复用原生媒体导入校验。
8. 身份：选择本机 Steam 账号名称与头像或访客。此步骤仅建立本地展示身份，不收集密码，不冒充 Steam 在线认证。

每一步可保留当前状态继续，也可返回；跳过不会伪装为安装成功。未完成准备或存在待核实系统操作时，不允许从地址跳转绕过状态门禁。

## 分盘与恢复

只处理在线可写、健康、未加密的基本 GPT NTFS 系统卷。无法确认 BitLocker 状态时拒绝修改；不会关闭加密或移动恢复分区。系统卷至少保留 128 GiB、60 GiB 空闲空间，新数据卷至少 32 GiB，并再次核对磁盘唯一身份、分区偏移及可收缩容量。电池设备必须接外部电源。

布局记录不是文件备份。只在新分区尚未建立时尝试将系统卷扩回；新卷一旦创建，故障恢复不会删除它。需通过 Windows 磁盘管理人工核实，合并前先转移文件。断电或存储故障可能需要离线恢复，应用不能承诺分区操作无风险。

## MSI 迁移与恢复

迁移从同版本公开 Release 取得完整包，因此必须先手动发布该版本的六个资产。网络、身份或校验失败时不卸载原应用。

迁移目录按当前 Windows SID 隔离。固定目录白名单复制数据并逐文件核验 SHA256；原件保留到新应用及前端返回健康信号。失败时尝试重装原 MSI、重开原档案。中断或断电时，目标盘 `.xinjing-maintenance` 留有完整 MSI、恢复说明、日志及记录，可人工恢复。无法确认完成的操作标记“待核实”，不自动重试。

用户可保留源数据；选择清理时，仅删除清单内且哈希未变化的源文件，保留其他文件。迁移后的 MSI 配置记录数据目录，后续手动升级仍沿用该位置。

## 本机验收限制

`ZHENJING_RESTRICT_WRITES_TO_D=1` 下，分区、迁移、驱动及 Steam 实际安装均在 Rust 边界拒绝。自动化仅执行真实只读采集、状态机和接口校验，以及 D 盘隔离数据的复制／哈希测试。不能将这些检查描述为真实分盘或安装验收。

发布前应在有快照的独立 Windows 虚拟机中补充：分盘成功与失败、迁移及断电恢复、官方安装器与 UAC、不同 Steam 布局的实际端到端验收。开发机不会执行这些系统修改。
