# 首页实现与真实数据边界

首页 `/` 是本机快捷启动工作空间，Steam 游戏库位于 `/library`。本次参考本地 NexBox 源码的首页职责及控制逻辑，保留臻境现有薄荷色玻璃、背景与公共导航；没有把 Steam 全库搬回首页，也没有实现手机远程配对、文件传输或远程桌面。

## 功能与数据来源

| 功能       | 真实来源与行为                                                                                              |
| ---------- | ----------------------------------------------------------------------------------------------------------- |
| 问候、日期 | Rust 读取当前进程的 Windows 用户名；设置中的自定义用户名优先。日期使用本机时间及所选语言。                  |
| 公告       | 读取臻境发布仓库 `surgar04/m78deguren` 的最新 Release；无可用网络时使用明确标记的本地 CHANGELOG 版本说明。  |
| 一言       | Hitokoto 官方接口；D 盘缓存有来源与获取时间，离线缓存明确标记；失败且无缓存时显示错误。                     |
| 随机图片   | Picsum 的真实图片及作者信息；Rust 限制下载大小、校验图片尺寸、解码重编码后缓存，可另存 D 盘或设为应用壁纸。 |
| 设备型号   | 复用硬件页采集服务的 CPU、GPU、内存和主板型号；不可用字段显示暂不可用。                                     |
| 快捷启动   | 系统文件选择器选择本机 EXE，验证 PE 文件，提取真实图标；可命名、标记游戏、启动、移除、拖动或按钮排序。      |
| 公共搜索   | 搜索快捷启动、真实 Steam 游戏及内置工具目录；Steam 结果跳转独立游戏库。                                     |
| 卡片可见性 | 复用设置服务保存的首页卡片选择；隐藏所有侧卡后主区自动扩展。                                                |

快捷启动数据仅存 UUID、名称、路径、游戏标记和实际启动时间，最多 128 项。移除仅删除臻境中的快捷记录及图标，不删除原 EXE。文件选择产生短期 Rust ticket，前端不能直接提交任意路径。启动不通过 shell，不接受附加命令；子进程可配置的临时、用户和应用数据环境全部指向 D 盘。外部程序自行硬编码的路径无法由本应用改写。

## 游戏模式与 Win 键

公共顶栏只有常规模式开关及设置入口。弹窗提供手动启停、游戏启动自动启用、游戏时禁用 Win 键和恢复入口；每项操作都有独立说明、勾选确认及执行回执。没有在顶栏展示竞技等三档选择。

游戏识别来自标记为游戏的快捷启动、Steam appinfo 中明确为 Game 的已安装目录，以及既有滤镜进程规则。未识别游戏可通过添加 EXE 并标记游戏补充；不把 Steam 软件一律当成游戏。PID 与创建时间同时核对，避免进程号复用。

常规模式仅对同用户、持续高于 CPU 阈值的普通后台进程尝试降低 CPU、I/O、内存优先级，以及系统支持并能读取原值时的 EcoQoS。前台程序、游戏家族、系统目录、安全、反作弊、平台及常见硬件控制程序跳过。不终止进程，不挂起进程，不提供竞技档隔离。具体 API 受当前系统及权限限制；不支持的可选字段不会伪造为已修改。

Win 键使用独立消息线程的低级键盘钩子，只处理左右 Win 键，并实时核对前台是否属于游戏家族。其他按键、桌面及非游戏窗口正常放行；按下与释放成对跟踪，避免切换前台后产生粘滞按键。关闭策略或退出助手后释放钩子。

进程原值在写入前落到 D 盘恢复记录。正常关闭、模式停止及父进程退出看门狗尝试恢复；失败项保留，界面提供再次恢复。崩溃遗留记录不会在下次启动时擅自写入进程，须明确确认。恢复同时核对 PID、创建时间、用户以及当前值是否仍是本工具写入值，保留其他程序后续主动调整。多个实例通过会话互斥锁避免同时控制。

## 工程结构

使用指南随应用内置，可离线阅读；反馈与项目交流统一使用本项目 GitHub Issues，不假设仓库已启用 Discussions，也不将尚未部署的臻境 README 当成现有在线文档。

- `src/pages/Overview.tsx`：首页编排、原生数据展示和可访问排序交互。
- `src/features/home/repository.ts`：TanStack Query 唯一业务状态源。
- `src/features/home/components/HomeActions.tsx`：快捷启动、逐项控制确认、公告及图片弹窗。
- `src/features/home/components/HomeDialogs.tsx`：公共搜索与弹窗编排。
- `src/lib/home-contracts.ts`、`src/lib/desktop.ts`：严格 IPC 契约及统一调用入口。
- `src-tauri/src/commands/home.rs`：主窗口限定、白名单操作及确认校验。
- `src-tauri/src/services/home/`：持久化、网络内容、EXE 启动与助手生命周期。
- `native.ps1` / `native.cs`：固定原生 API 桥接，不接受任意脚本；Rust 主进程无 unsafe。

修改快捷记录与顺序使用配置版本比较，过期请求必须刷新后重试，避免多次操作覆盖新数据。Zustand 仅保存界面偏好和 Steam 收藏；游戏模式与 Win 策略不再由前端布尔值冒充系统状态。

## 存储与网络限制

首页数据在应用数据根下的 `home/`：`workspace.json`、`icons/`、`cache/`、`process-recovery.json` 及 `launch-data/`。所有读写经过 D 盘及目录链接检查。下载、临时文件、编译助手缓存与诊断同样位于 D 盘；清数据前先关闭原生控制助手。

HTTP 客户端复用连接并设置连接、总时限及响应大小限制。仅允许 GitHub API、Hitokoto、Picsum 及其指定图片 CDN 的 HTTPS 地址和重定向，不放开任意 URL 或 CSP。网络与图片处理不在异步命令中直接运行阻塞 I/O；图片解码及原生对话框进入阻塞工作线程。

## 验证方式与边界

`test:home:native` 编译实际固定 C# 桥，读取 EXE 图标及自身只读 API，验证助手配置关闭和正常退出；不启用进程压制、输入钩子或系统安装。`test:home:desktop` 使用独立 D 盘档案，通过真实桌面 IPC 检查数据来源、确认门槛和 1200/760 宽度适配。Rust 测试覆盖路径、配置、并发版本及排序边界；前端测试覆盖契约和旧偏好迁移。

开发验收不得自动执行游戏模式、Win 键拦截、账号修改、驱动安装或其他系统写入。此边界意味着编译及确认流程验证通过，不能冒充已对所有电脑、游戏及系统权限实测。实际验收结果以 `.cache/verification/` 的当次日志为准。

2026-10-28 本机验证：前端 18 个文件、61 项测试通过；Rust 63 项通过、6 项跳过。真实桌面检查覆盖原生数据、搜索、确认门槛、1200/760 宽度，以及真实 D 盘 EXE 的图标、启动、拖放/按钮排序、刷新持久化和移除保留原文件。随机图片已实际导入为应用壁纸并通过自有资源协议读取；自定义用户名和卡片隐藏已通过设置界面验证。隔离档案中的测试入口与偏好已恢复。

原生 EXE 选择器可打开，但 Windows 截图服务连续返回 `window capture timed out`，未完成选择器和另存对话框的自动化操作。后续启动、排序及移除检查使用隔离档案登记的既有真实 EXE；不将这一结果记为“选择器全流程实测通过”。游戏控制仅检查确认门槛和只读 ABI，不执行进程压制或输入钩子。

旧的 `data/demo.ts`、演示游戏数组、假读数、假日期及 `VITE_HOME_DATA_SOURCE` 分支已删除。`build:empty` 仅保留兼容构建入口，当前普通构建同样不含首页演示数据。品牌、背景与装饰头像属于静态界面素材，不冒充真实账号或采集数据。
